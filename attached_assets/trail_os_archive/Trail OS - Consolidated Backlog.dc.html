Defect · the validation page was reporting false failures

It claimed 9 of 18 objects accessible. The real figure is 17 of 18 — nine failures were the connector proxy throttling at twenty requests per ten seconds, not inaccessibility. Worse, the Contact panel reported zero custom fields and listed fifteen as missing, when all of them exist; a throttled describe had been read as absence.

Probes are now batched with a retry that honours the server's back-off. A throttled probe that still fails reports as undetermined in amber, never as missing — and the server now guarantees a missing-fields list cannot be produced when the describe itself failed. The page takes four seconds instead of being instant and wrong.

Decisions — all settled

All six are now resolved or deliberately parked. One action remains rather than a decision: the migration into Salesforce tomorrow, which fixes the identifier question by doing it.

Resolved — the learner surface is Trail OS, with Slack as the communication layer

Settled 4 August. Trail OS is where the work and the coaching happen; Slack carries conversation, nudges and quest delivery, likely open in a side panel alongside it. Not Experience Cloud, not a separate product, not Slack alone.

One design consequence to settle before either surface is built. Because the two are open at the same time rather than used in turn, Penny in Trail OS and Penny in Slack are one conversation with two windows. Her memory has to be keyed on the person rather than the surface — otherwise a learner asks something in Slack, switches to Trail OS, and finds she has forgotten it.

Resolved — Foundations gets a fifth trail configuration

Settled 4 August, to be created through the Penny Configuration interface so that interface is exercised at the same time. The configuration object is all free text with no restricted picklists, so nothing will silently reject. Trail ID and Penny Role are the two required fields, and the existing four use hyphenated identifiers — guided-trail, explorer-journey, trail-of-mastery, community-alumni.

One thing to check first. The trail field on Contact is a picklist. If it has no Foundations value, the configuration can be created but no learner can be assigned to it — the same failure that hid the interaction log problem.

Resolved — "Trail Quests" stays

Confirmed 4 August as deliberate house vocabulary rather than borrowed ecosystem language. Worth writing into the brand book as an intentional exception so it is not raised again. Separately, one genuinely prohibited term does sit in a live field name on Contact — worth folding into the next brand-book pass, where the label can be changed without a schema migration.
