PURPOSE  This PRD defines all product requirements for Trail OS Phase 2. It covers four sprint themes: Live Penny AI (Gemini wire-up + RAG), Live Data (Salesforce queries replacing prototype data), Trail Quests and Career Review delivery, and Penny POC retirement. This document is the contract between Angela (product owner) and Hugh (implementation). Every feature, user story, acceptance criterion, and non-functional requirement is defined here.
SECTION 1   —   Product Overview
## 1.1  Product Vision
Trail OS is the unified internal operating system for Transition Trails Academy. Phase 2 completes the platform by replacing every prototype data fixture with live connections, wiring Penny to a live AI engine, and retiring the standalone Penny POC Replit app. When Phase 2 is done, the organization operates entirely through Trail OS — no separate tools, no disconnected dashboards, no prototype scaffolding.
## 1.2  Problem Statement
Phase 1 delivered a navigable, role-aware platform with live Salesforce and Slack integrations. However, three critical gaps prevent Trail OS from becoming the operational center of gravity:
Penny responds with pattern-matched text — not live AI. Coaches and learners cannot trust her output for real coaching.
All learner, program, and signal data is hardcoded prototype fixtures. No operational decision can be made from current screens.
The Penny POC Replit app continues to serve as the real Penny — meaning the organization runs on two disconnected systems.
## 1.3  Goals and Non-Goals
## Goals
Wire Ask Penny and Test Penny to live Gemini 2.5 Flash with contextual prompt architecture.
Replace all 11 hardcoded Phase 2 data items with live Salesforce queries.

SECTION 2   —   Technical Architecture
## 2.1  Dual Engine Architecture
Trail OS Phase 2 operates on the Dual Engine model: Salesforce is The Brain (data, records, truth) and Gemini is The Voice (reasoning, generation, coaching). These two engines are complementary and non-overlapping.
Layer
Responsibility
Salesforce (The Brain)
Learner profiles, quest records, career profiles, conversation logs, program data, knowledge governance, custom objects (W-000222)
Gemini 2.5 Flash (The Voice)
Ask Penny responses, Test Penny, Trail Quest generation, Career Review scoring, Weekly Intelligence synthesis, Penny Recommendations
Trail OS API Server
Express 5 broker between Salesforce, Gemini, Slack, and the React frontend. All integration routes live in /artifacts/api-server/src/routes/
Agentforce (Future — p2-agentforce)
Coexistence model with Penny defined but not implemented in Phase 2. Handoff protocol deferred.

## F-100  Ask Penny — Live Gemini Response (Right Rail)
The Ask Penny tab in the right rail currently returns hardcoded pattern-matched responses. Phase 2 wires it to a live Gemini endpoint with the 5-layer prompt architecture.
## User Stories
As a coach, when I open any page and type a question in Ask Penny, I receive a live AI response grounded in the current page context and selected learner.
As a Power user, Ask Penny responses about capabilities should reflect the capability I have selected in the workspace — not generic platform guidance.
As an admin, I need to see the Gemini model and prompt layer used in each Ask Penny response for quality auditing.
## Functional Requirements
Ask Penny input field and send button wired to POST /api/gemini/ask.
Request payload includes: learner context (if context is set), current page/section, selected object (if in workspace), prompt template ID (L5).
Response streamed to the Ask Penny panel in the right rail with typing indicator during generation.
Session Info panel (visible to Admin+) shows: model used, prompt layers assembled, token count, latency.
Responses saved to Penny_Conversation__c with learner_id, session_id, message_role, content, and timestamp.
## Acceptance Criteria
User types "What should I work on this week?" — Penny returns a live Gemini response referencing the learner's current context within 3 seconds.
Two different questions to the same Penny session return related but distinct responses (not identical pattern text).
Admin Session Info panel shows model: "gemini-2.5-flash", layers: 5, latency in ms.
Penny_Conversation__c record is created in Salesforce after each exchange.

## F-201  Career Profile Review
Career Profile Review is one of Penny's four core POC capabilities. It provides 5-dimension scoring of resume bullets and LinkedIn content without fabricating credentials.
## User Stories
As a learner, I can paste my raw resume bullets into Penny and receive structured feedback across 5 dimensions without Penny inventing experience I don't have.
As a coach, I can see a learner's Career Profile Review scores and Penny's recommendations in the Learner Detail view.
## 5-Dimension Scoring Model
Dimension
What It Measures
Output
D1
Impact Framing
Does the bullet show measurable outcomes vs. just tasks?
Score 1–5 + specific fix if <4
D2
Salesforce Relevance
Does the bullet connect to Salesforce Admin skills employers look for?
Score 1–5 + suggested SF terminology if <4
D3
Specificity
Are details (names, numbers, systems) present and verifiable?
Score 1–5 + specificity prompt if <4
D4
Transferability
Would a hiring manager outside Salesforce understand the value?
Score 1–5 + plain-language reframe if <4
D5
Authenticity
Is the language genuine to the learner? No fabricated credentials?
Pass/Fail + guardrail note if fabrication detected
## Functional Requirements
Career Review input: text area accepting raw resume bullets or LinkedIn About section text.
POST /api/gemini/career-review sends text + learner context to Gemini with D1–D5 scoring prompt.
Response parsed into structured scores and saved to Penny_Career_Profile__c.
Career Profile tab on Learner Detail displays: dimension scores, Penny's specific rewrites, and overall readiness indicator.
Penny never fabricates: if no quantifiable data exists in the input, D3 score reflects that — Penny does not invent numbers.
## Acceptance Criteria
Paste raw bullet "Helped with Salesforce" → all 5 dimensions scored with specific improvement suggestions returned.
D5 Authenticity returns Pass for real bullet, Fail + guardrail message if Penny detects invented credentials.
Penny_Career_Profile__c record created in Salesforce with all 5 dimension scores.
Career Profile tab on learner detail shows the review with edit history.

## F-301  Penny RAG — Knowledge Source Retrieval
RAG (Retrieval-Augmented Generation) gives Penny the ability to retrieve from the Knowledge Library when answering learner questions. Only sources approved for Penny (Penny_Approved__c = true, Trust Level = Authoritative or Trusted) are eligible.
## User Stories
As a learner, when I ask Penny about the RESOLVE framework, she retrieves from the actual RESOLVE Handbook rather than generating from training data alone.
As an admin, I control which knowledge sources Penny can retrieve from through the Knowledge Sources governance workflow.
## Functional Requirements
Knowledge source retrieval integrated into L4 of the prompt architecture.
Only sources where Trust Level IN (Authoritative, Trusted) AND Penny_Approved__c = true are eligible for retrieval.
Retrieval triggered when: Ask Penny query contains keywords matching a source topic, or capability template specifies required sources.
Retrieved content injected into L4 prompt layer with source attribution.
Penny response includes "Sources consulted:" footer when RAG is triggered (visible to Power+ users).
Knowledge Sources governance UI updated: "Approve for Penny" toggle on Sources workspace activates retrieval.
## Acceptance Criteria
Ask Penny "What is the Recognize phase of RESOLVE?" → response references content from RESOLVE Handbook source (confirmed by Sources Consulted footer).
Sources with Trust Level = Unverified do NOT appear in Penny responses even if query matches.
Toggling Penny_Approved__c off for a source removes it from retrieval within 60 seconds.
