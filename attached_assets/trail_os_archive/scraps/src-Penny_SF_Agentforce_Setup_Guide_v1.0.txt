## 1. What You Are Building
Penny is a Salesforce Agentforce Service Agent — an AI coaching companion that lives inside TT&apos;s Salesforce org, reads real learner data, and delivers personalized coaching through Slack and the Penny mobile app. She is powered by Google Gemini 2.5 Flash as an external model, not Einstein&apos;s default AI.
This guide covers every configuration step: creating the agent, connecting Gemini, building the 7-layer prompt architecture as Agentforce topics and actions, wiring Slack, and verifying the first live conversation. It also covers the NPSP-specific considerations that apply because TT&apos;s learner data lives on Contact and Program Engagement — not on a standard CRM lead or account.
Why Gemini, not Einstein default
Penny&apos;s voice — the Socratic questioning style, the warmth, the way she asks before telling — was trained into the POC using Gemini 2.5 Flash. That voice is a product decision, not a technical one. If you switch to Einstein&apos;s default model to &apos;just get it working,&apos; Penny will not sound like Penny. Wire Gemini first. Test with Gemini. Do not use the default model for any live conversation.

## 3. NPSP — What Hugh Needs to Know
TT&apos;s Salesforce org runs NPSP (Nonprofit Success Pack) — confirmed with npsp__, npe01__, npe03__, npe4__, and pmdm__ namespaces all installed. This changes several things about how Penny reads learner data compared to a standard Sales Cloud org.
## 3.1 The NPSP Contact Model
In NPSP, Contact is the primary record for a person — not Lead, not Account. Every Transition Trails learner is a Contact. The Account associated with a learner Contact is a Household Account (automatically created by NPSP), not an organization account.
What this means for Penny
When GetLearnerContext reads a learner record, it reads from Contact — not Lead, not Account. If you accidentally write a Flow that queries Account thinking it will find learner data, you will get a Household Account with no useful information. Always query Contact directly.
## 3.2 Program Engagement (pmdm__ProgramEngagement__c)
TT uses NPSP&apos;s Program Management Module (PMM) — the pmdm__ namespace. A learner&apos;s trail assignment and cohort enrollment live on pmdm__ProgramEngagement__c, not on Contact directly.
The GetLearnerContext action needs to query both objects:
-- Query Contact for personal + Penny coaching fields
SELECT Id, FirstName, LastName, Email,
Penny_Trail_Config__c, Penny_Current_Goal__c,
Penny_Current_Phase__c, Penny_Current_Blockers__c,
Penny_Coaching_Tone__c, Penny_Confidence_Score__c,
Slack_User_ID__c
FROM Contact
WHERE Id = :learnerId
-- Query Program Engagement for cohort + trail enrollment
SELECT Id, pmdm__Program__r.Name, pmdm__ProgramStatus__c,
pmdm__CohortId__r.Name, pmdm__Role__c,
pmdm__StartDate__c
FROM pmdm__ProgramEngagement__c
WHERE pmdm__Contact__c = :learnerId
AND pmdm__ProgramStatus__c = &apos;Active&apos;
ORDER BY pmdm__StartDate__c DESC
LIMIT 1
## 3.3 NPSP Triggers and Automation
NPSP runs significant background automation on Contact save — relationship management, household naming, soft credit rollups. Be aware of two things:
When Penny&apos;s LogInteraction action writes to Penny_Interaction_Log__c, it does NOT touch Contact directly, so NPSP triggers do not fire. Safe.
When the AwardBadge action creates a Penny_Gamification__c record with a Lookup to Contact, NPSP does not care. Penny&apos;s custom objects are invisible to NPSP automation. Safe.
The one risk: if you add a Lookup from a Penny object to pmdm__ProgramEngagement__c, test carefully. PMM has its own automation that can cascade unexpectedly. Keep Penny&apos;s lookups on Contact only unless there is a specific reason.

## 7. Build the Actions — The 7-Layer Prompt
Each action is a Salesforce Flow that reads data from one or more objects and returns it as output variables. Agentforce assembles the outputs into the final prompt at call time. Build them in this order — each depends on the objects built in W-000222.
## 7.1 GetTrailConfig — Layer 2
## What it does
Reads the Penny_Trail_Config__c record for the learner&apos;s assigned trail and returns the trail persona context for Layer 2 of the prompt.
## Flow type: Autolaunched Flow (No Trigger)
## Input variables
learnerId (Text) — the Contact Id of the learner
## Steps
Get Records: Query Contact WHERE Id = {!learnerId}. Store Penny_Trail_Config__c lookup field.
Get Records: Query Penny_Trail_Config__c WHERE Id = {!Contact.Penny_Trail_Config__c} AND Is_Active__c = true. Limit 1.
Decision: if no active config found — assign default values (Trail_ID__c = &apos;guided_trail&apos;, Penny_Role__c = &apos;Coaching Companion&apos;, Tone__c = &apos;Warm and encouraging&apos;).
Assignment: set output variables penny_role, tone, focal_points, specific_instructions from the trail config record.
## Output variables
trail_id (Text)
penny_role (Text)
tone (Text)
focal_points (Text)
specific_instructions (Text)
NPSP note for GetTrailConfig
The Penny_Trail_Config__c lookup is on Contact, which in NPSP may have the Household Account as its primary related account. The Flow queries Contact directly by Id — NPSP account relationships are irrelevant here. No NPSP-specific handling needed.
## 7.2 GetLearnerContext — Layer 3
## What it does
Reads Contact + pmdm__ProgramEngagement__c and returns the learner&apos;s coaching context for Layer 3. This is the most NPSP-specific action in the entire build.
## Flow type: Autolaunched Flow (No Trigger)
## Input variables
learnerId (Text)
## Steps
Get Records: Query Contact WHERE Id = {!learnerId}. Get fields: FirstName, LastName, Penny_Current_Goal__c, Penny_Current_Phase__c, Penny_Current_Blockers__c, Penny_Coaching_Tone__c, Penny_Confidence_Score__c, Penny_Onboarding_Complete__c.
Get Records: Query pmdm__ProgramEngagement__c WHERE pmdm__Contact__c = {!learnerId} AND pmdm__ProgramStatus__c = &apos;Active&apos;. Order by pmdm__StartDate__c DESC. Limit 1. Get fields: pmdm__Program__r.Name, pmdm__Cohort__r.Name, pmdm__Role__c.
Assignment: build learner_context output by combining both record sets.
## Output variables
learner_name (Text)
current_goal (Text)
current_phase (Text)
current_blockers (Text)
coaching_tone (Text)
confidence_score (Text)
program_name (Text)
cohort_name (Text)
onboarding_complete (Boolean)
NPSP critical: pmdm__ field access
The Penny Agent permission set MUST have Read access on pmdm__ProgramEngagement__c, pmdm__Program__c, and pmdm__Cohort__c (see Section 3.4 object permissions table). If these are missing, the Flow will fail with INSUFFICIENT_ACCESS_ON_CROSS_REFERENCE_ENTITY. Add them before testing this action.
## 7.3 GetActiveQuest — Layer 5
## What it does
Reads the learner&apos;s active quest assignment from Course_Module_Activity__c and the full quest brief from Course__c.
## Flow type: Autolaunched Flow (No Trigger)
## Input variables
learnerId (Text)
## Steps
Get Records: Query Course_Module_Activity__c WHERE Contact__c = {!learnerId} AND Status__c = &apos;In Progress&apos;. Order by CreatedDate DESC. Limit 1.
Get Records: Query Course__c WHERE Id = {!Activity.Course__c}. Get quest brief fields.
Decision: if no active quest — return empty strings. Penny handles gracefully.
Assignment: set output variables from the quest record.
## Output variables
quest_title (Text)
quest_brief (Text)
quest_category (Text)
quest_difficulty (Text)
## 7.4 GetCareerReview — Layer 6
## What it does
Reads the most recent Penny_Career_Review__c record for the learner. Only returns data if the review was conducted within the last 30 days.
## Flow type: Autolaunched Flow (No Trigger)
## Input variables
learnerId (Text)
## Steps
Get Records: Query Penny_Career_Review__c WHERE Learner__c = {!learnerId}. Order by Reviewed_At__c DESC. Limit 1.
Formula: calculate days since Reviewed_At__c. If > 30, return empty strings.
Assignment: set output variables from review record if within 30 days.
## Output variables
readiness_label (Text)
area_scores (Text)
target_role (Text)
## 7.5 GetMemoryWindow — Layer 7
## What it does
Reads the last N Penny_Interaction_Log__c records for the learner and returns them as a formatted conversation history. Default window is 5 turns. Maximum is 20.
## Flow type: Autolaunched Flow (No Trigger)
## Input variables
learnerId (Text)
windowSize (Number) — default 5, max 20
## Steps
Get Records: Query Penny_Interaction_Log__c WHERE Learner__c = {!learnerId}. Order by CreatedDate DESC. Limit {!windowSize}.
Loop: for each record, build a formatted string &apos;Learner: [message] Penny: [response]&apos;
Assignment: concatenate all turns into conversation_history output variable.
## Output variables
conversation_history (Text) — last N exchanges as formatted text
turn_count (Number) — actual number of turns returned
## 7.6 LogInteraction — Write Every Exchange
## What it does
Writes every Penny exchange to Penny_Interaction_Log__c. Called at the end of every conversation turn, regardless of topic.
## Flow type: Autolaunched Flow (No Trigger)
## Input variables
learnerId (Text)
userMessage (Text)
pennyResponse (Text)
promptMode (Text)
source (Text) — slack_dm / slack_mention / mobile / dashboard
## Steps
Create Records: Penny_Interaction_Log__c with all input variables. CreatedDate is automatic.
## Output variables
logId (Text) — the Id of the created record
## 7.7 AwardBadge — Gamification Engine
## What it does
Awards a program badge to a learner. Creates a Penny_Badge__c record and a Penny_Gamification__c record. Fires a Slack DM celebration via SlackAppConversationEvent.
## Flow type: Autolaunched Flow (No Trigger)
## Input variables
learnerId (Text)
badgeKey (Text) — one of: first_deploy, sprint_complete, qa_champion, client_win, code_reviewer, career_ready
awardedBy (Text) — &apos;system&apos; or coach User Id
note (Text) — optional coach note
## Steps
Decision: check if learner already has this badge key. If yes — stop. No duplicate badges.
Formula: set badge_name based on badge_key (e.g. first_deploy → &apos;First Deployment&apos;).
Formula: set points based on badge_key (first_deploy = 50, sprint_complete = 100, qa_champion = 75, client_win = 150, code_reviewer = 50, career_ready = 200).
Create Records: Penny_Badge__c with learnerId, badgeKey, badgeName, awardedBy, note, Awarded_At = now.
Create Records: Penny_Gamification__c with learnerId, points, reason = &apos;Badge awarded: &apos; + badgeName.
Platform Event: fire SlackAppConversationEvent to send DM to learner&apos;s Slack_User_ID__c with celebration message.
## Output variables
badgeId (Text) — Id of the created badge record
success (Boolean)

## 9. Wire the First Deploy Badge Trigger
When a learner&apos;s DevOps Center deployment succeeds for the first time, Penny should automatically award the &apos;First Deployment&apos; badge and send them a Slack DM. This is wired via a Record-Triggered Flow on sf_devops__Deployment_Result__c.
## Flow: Award First Deploy Badge on Successful Deployment
Flow Type: Record-Triggered Flow
Object: sf_devops__Deployment_Result__c
Trigger: When a record is created
Condition: Status = &apos;Succeeded&apos; (check the actual picklist value in your org)
Get Related Contact: from the deployment result, traverse to the Work item, then to the Assignee user, then to the Contact record via a custom field or email match
Subflow: call AwardBadge with badgeKey = &apos;first_deploy&apos;, awardedBy = &apos;system&apos;
Check the deployment result object fields first
Run: SELECT Id, QualifiedApiName, Label FROM FieldDefinition WHERE EntityDefinition.QualifiedApiName = &apos;sf_devops__Deployment_Result__c&apos; — confirm the Status picklist values and how the result relates back to a Work item and user before building the Flow.
